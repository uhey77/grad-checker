# 卒業要件チェッカー 要件定義書

| 項目 | 内容 |
|---|---|
| 文書版 | 1.0（初期開発版） |
| 作成日 | 2026年10月9日 |
| 対象 | 東京工科大学 コンピュータサイエンス学部 先進情報専攻 人工知能コース |
| 目的 | 模擬学務データベースにある成績を参照し、卒業単位要件の達成状況を可視化する |
| 根拠資料 | 2026年度学生便覧「教育課程表」冊子85～88ページ、「卒業要件」冊子93～94ページ |

## 1. 背景と目的

学生が成績一覧と学生便覧を見比べて卒業に必要な単位を確認する際、総単位数だけでなく、必修科目、選択必修科目、科目群別の条件を確認する必要がある。手作業では不足条件の見落としや集計の誤りが起こりやすい。

本システムは、大学が管理する成績情報をもとに、取得済み科目、取得単位数、残り必要単位数、卒業単位要件の達成状況を自動表示する。学生が「どの区分の何が不足しているか」を把握できることを目的とする。

提供形態はCampus Square内の一機能を想定する。ただし、今回の開発は独立したWebアプリケーションとし、実際のCampus Squareには接続しない。大学の成績システムを模したRDBを使用する。

## 3. 利用者と基本利用フロー

学生は学籍番号とパスワードでログインする。認証後は本人の学生情報、成績情報、適用カリキュラムを取得し、ダッシュボードに卒業単位要件の達成状況を表示する。学生は科目一覧へ移動し、科目群別の取得状況を確認できる。利用終了時にログアウトする。

開発者は学生・認証情報、科目マスタ、成績情報、卒業要件マスタをSQLまたはシードデータで準備する。学生画面にはこれらを書き換える操作を設けない。

### 3.1 確定したデータ運用

1. 複数のテスト学生アカウントを事前に用意する。
2. 学生ごとに異なる成績データをRDBに登録する。
3. ログインすると、その学生の情報だけが表示される。
4. 成績データはSQLやシードデータで事前に投入し、学生画面から変更できないようにする。
5. 取得済み単位数と卒業要件は、画面表示時に自動集計・判定する。

## 6. 卒業単位要件

### 6.1 根拠資料と数値の採用方針

本書は、2026年度学生便覧の先進情報専攻の教育課程表と卒業要件表を基準とする。冊子94ページはPDFの96ページ目に対応する。

会話で提示された画像には「必修55単位・選択必修50単位」の表がある。この数値は便覧の社会情報専攻の表と一致する。今回の対象は先進情報専攻・人工知能コースのため、「必修58単位・選択必修47単位」を採用する。過去の会話で使った55単位・50単位は本書の判定値には使用しない。

### 6.2 大分類別要件

| 大分類 | 必修 | 選択必修 | 選択算入 | 合計 |
|---|---:|---:|---:|---:|
| 実学基礎科目 | 16単位 | 14単位 | 8単位以上 | 38単位以上 |
| 専門基礎教育科目 | 21単位 | 18単位 | 3単位以上 | 42単位以上 |
| 専門教育科目 | 21単位 | 15単位 | 8単位以上 | 44単位以上 |
| 合計 | 58単位 | 47単位 | 19単位以上 | 124単位以上 |

必修は単位数の達成に加え、対象必修科目を全て取得していることを条件とする。選択必修は以下の科目群別要件を全て満たす必要がある。

### 6.3 科目群別要件

| 大分類 | 科目群・集計範囲 | 必修 | 選択必修 | 内訳条件 |
|---|---|---:|---:|---|
| 実学基礎科目 | 総合・人文・社会・自然科学・ウェルビーイング | なし | 合計10単位以上 | 人文2単位以上、社会2単位以上を含む |
| 実学基礎科目 | 外国語 | 4単位 | 2単位以上 | 必修科目を全て取得 |
| 実学基礎科目 | 情報・数理 | 6単位 | 2単位以上 | 必修科目を全て取得 |
| 実学基礎科目 | 社会人基礎 | 6単位 | なし | 必修科目を全て取得 |
| 実学基礎科目 | 社会連携 | なし | なし | 選択として実学基礎科目に算入 |
| 専門基礎教育科目 | 数理 | 4単位 | 4単位以上 | 必修科目を全て取得 |
| 専門基礎教育科目 | マネジメント | なし | 2単位以上 | 指定科目から取得 |
| 専門基礎教育科目 | コンピュータ・ビジネス | 17単位 | 12単位以上 | 必修科目を全て取得 |
| 専門教育科目 | コア科目 | なし | 12単位以上 | 人工知能コースで選択必修に指定された科目から取得 |
| 専門教育科目 | 実験・総合 | 21単位 | 3単位以上 | 必修科目を全て取得し、知能の専門演習から取得 |

表に示していない小分類の必要単位数を独自に追加しない。例えば自然科学やウェルビーイングは取得単位を表示するが、各分類に独立した最低単位数は設定しない。選択8単位・3単位・8単位は各大分類全体の条件であり、各科目群に同じ値を設定しない。

### 6.4 人工知能コースの種別適用

科目一覧と判定には、教育課程表の共通種別とコース別種別を統合した「人工知能コースでの種別」を使用する。共通欄が選択であっても、人工知能コース欄で選択必修となる科目は選択必修として扱う。

人工知能コースのコア科目で選択必修となる科目は以下の8科目であり、各2単位、合計から12単位以上を取得する。

- コンピュータアーキテクチャ
- ソフトウエアエンジニアリング
- 情報セキュリティ
- 自然言語処理
- データ構造とアルゴリズム
- 人工知能
- データベース
- データサイエンス

実験・総合の選択必修は「先進情報専門演習・知能Ⅰ」「先進情報専門演習・知能Ⅱ」「先進情報専門演習・知能Ⅲ」の各3単位から、3単位以上を取得する。基盤・人間の専門演習は人工知能コースでは選択として扱う。

上記にないコア科目は、対象教育課程表で履修対象となるものを選択として扱う。科目の開講時期、GPAによる履修可否などは、履修登録機能を持たない本システムでは判定しない。

## 7. 集計・判定ルール

### 7.1 成績状態と単位算入

| 状態 | 取得済み単位へ算入 | 初期画面の扱い |
|---|---|---|
| 取得済み | する | 背景色と「取得済み」ラベルで表示 |
| 履修中 | しない | 「未取得」として扱い、履修中の詳細表示は将来対応 |
| 不合格 | しない | 「未取得」として扱い、不合格の履歴表示は将来対応 |
| 未履修・成績記録なし | しない | 「未取得」として表示 |

成績データでは履修中・不合格を区別して保持できるようにする。初期開発の不足単位計算では、これらを取得見込みとして加算しない。

### 7.2 重複計上の防止

- 同一学生が同一科目を再履修しても、取得単位は科目ごとに1回だけ算入する。
- 不合格の後に合格した科目は取得済みとして扱う。
- 同一科目が大分類、科目群、小分類の表示に現れても、総取得単位数には1回だけ算入する。
- 人文2単位などの内訳条件は上位条件の一部であり、上位条件へ追加して二重計上しない。
- 科目名ではなく科目ID等の安定した識別子で重複を判定する。

### 7.3 必修科目

対象カリキュラムの全必修科目について取得の有無を確認する。同じ大分類に余剰の選択・選択必修単位があっても、未取得の必修科目を補えない。未取得科目の名前と単位数を表示する。

### 7.4 選択必修と超過単位

選択必修は科目群別に集計する。ある群の超過単位で別の群の選択必修不足を補わない。

各選択必修群について、次のように算出する。

```text
選択必修への算入単位 = min(取得済みの選択必修単位, その群の必要単位)
超過単位 = max(取得済みの選択必修単位 - その群の必要単位, 0)
選択必修の不足単位 = max(その群の必要単位 - 取得済みの選択必修単位, 0)
```

総合・人文・社会・自然科学・ウェルビーイングは、5分類をまとめた1つの選択必修群として扱う。必要単位は10単位とし、人文2単位・社会2単位は別の内訳条件として判定する。取得済み単位が10単位以上でも人文または社会が不足していれば、その条件は未達成のままとする。

各大分類の選択算入単位は、次の式で求める。

```text
選択算入単位 = 直接取得した選択科目の単位
             + 同じ大分類に属する選択必修群の超過単位の合計
```

換算先は同じ大分類に限定する。超過分は集計上の配分であり、科目マスタの種別や成績記録を変更しない。総取得単位数にも換算分を追加しない。

例：外国語の選択必修を4単位取得している場合、必要な2単位を外国語の選択必修として算入し、超過2単位を実学基礎科目の選択へ換算する。総取得単位数に算入されるのは実際に取得した4単位のみである。

### 7.5 不足単位数の表示

```text
総不足単位数 = max(124 - 総取得済み単位数, 0)
条件別不足単位数 = max(その条件の必要単位数 - その条件への算入単位数, 0)
大分類の合計不足単位数 = max(その大分類の必要合計単位数 - その大分類の取得済み単位数, 0)
```

総不足単位数とカテゴリ別・条件別不足単位数は別々に表示する。カテゴリ別不足単位数を合計して総不足単位数にしない。親条件と子条件の不足も単純に加算しない。

総不足が0でも、必修科目や科目群別条件が不足していれば未達成とする。例えば、総取得124単位で必修科目が未取得なら「総不足0単位、必修条件未達成」と表示する。

### 7.6 全体の達成判定

以下を全て満たした場合に「卒業単位要件：達成」と表示する。

1. 総取得済み単位数が124単位以上である。
2. 対象カリキュラムの必修科目を全て取得している。
3. 選択必修の各科目群の必要単位数を満たしている。
4. 人文2単位以上・社会2単位以上の条件を満たしている。
5. 各大分類の選択算入単位が所定の単位数以上である。
6. 各大分類の合計単位数が38・42・44単位以上である。

表示は「卒業単位要件の達成状況」とし、正式な卒業認定を意味する表現は使用しない。画面には「本システムが対応する単位要件に基づく判定です」と説明を表示する。

## 8. 画面要件

### 8.1 ログイン画面

学籍番号入力欄、パスワード入力欄、ログインボタン、エラー表示領域を設ける。パスワードは伏字とする。認証失敗時は学籍番号の存在を区別せず、入力情報が正しくないことを表示する。

### 8.2 ダッシュボード

学生情報、総単位数の進捗、カテゴリ別進捗、区分別進捗、未達成条件を表示する。科目一覧への移動とログアウトを可能にする。

| 表示領域 | 内容 |
|---|---|
| 学生情報 | 学籍番号、氏名、学部、専攻、コース |
| 全体 | 必要124単位、取得済み単位数、総不足単位数、全体の達成状況 |
| 大分類別 | 実学基礎、専門基礎教育、専門教育の必要・取得・不足単位数 |
| 種別別 | 各大分類の必修、選択必修、選択算入、合計の状況 |
| 科目群・小分類別 | 必要単位が設定された群の達成状況と、人文・社会の内訳条件 |
| 未取得必修 | 未取得科目名、単位数 |
| 換算内訳 | 直接取得した選択単位と、選択必修からの換算単位 |

カテゴリ別表示はダッシュボード内に設ける。総単位数とカテゴリ別不足単位数は独立した領域に表示し、意味を区別する。科目一覧は別画面とする。

種別別の表では、取得済みの実単位数と条件への算入単位数が異なる場合に両者を識別できるようにする。必要単位が設定されていない分類は「個別最低単位なし」とし、不足単位を独自に計算しない。

### 8.3 科目一覧画面

学生便覧の教育課程表に近い表形式とし、大分類ごとに表を区切る。各科目について、科目群、科目名、人工知能コースでの種別、単位数、取得状況を表示する。科目群の順序は便覧に合わせる。

取得済み科目は背景色を変更し、「取得済み」ラベルを併記する。未取得科目は「未取得」と表示する。チェックボックス等による取得状態の編集操作は設けない。

### 8.4 遷移と更新

未認証のアクセスはログイン画面へ案内する。認証後はダッシュボードを表示する。ダッシュボードと科目一覧を相互に移動でき、どちらからもログアウトできる。

成績更新の反映は、画面再読み込み・再取得時に行う。自動ポーリングやリアルタイム通知は初期開発の要件に含めない。

## 9. データ要件

### 9.1 管理する情報

以下は論理上の管理単位であり、最終的な物理テーブル名や列名は基本設計で確定する。

| 管理単位 | 主な情報 |
|---|---|
| 学生 | 学生ID、学籍番号、氏名、学部・専攻・コース、入学年度、適用カリキュラム |
| 認証情報 | ユーザーID、学生ID、パスワードハッシュ、利用状態 |
| 所属課程 | 学部、専攻、コースを識別するIDと名称 |
| カリキュラム | カリキュラムID、対象課程、名称、根拠資料 |
| 科目マスタ | 科目ID、科目コード、科目名、単位数 |
| 課程別科目定義 | カリキュラムID、科目ID、大分類、科目群、小分類、種別、表示順 |
| 成績情報 | 学生ID、科目ID、成績、単位取得状態、履修年度・学期、履修回次 |
| 分類マスタ | 分類ID、名称、親分類、表示順 |
| 卒業要件マスタ | 条件ID、適用カリキュラム、対象分類・科目集合、条件種別、必要単位数、換算先 |

### 9.2 データ間の関係

- 学生と科目は成績情報によって関連付ける。科目マスタと個々の学生の成績を分離する。
- 科目の種別・分類は適用課程に関連付ける。将来、同じ科目を別コースで異なる種別として扱えるようにする。
- 卒業要件は科目のカテゴリ情報とは別に管理する。複数分類をまとめた10単位条件と、人文2単位・社会2単位条件を独立した条件として表現できるようにする。
- 初期開発では1つのカリキュラムを全対象学生に適用する。入学年度別の切替は行わない。

### 9.3 整合性

- 学籍番号は重複しない。
- 成績の学生ID・科目ID、課程別科目定義のカリキュラムID等に参照整合性を持たせる。
- 科目単位数、必要単位数に不正な負数を登録しない。
- 同じカリキュラム内で同じ科目の課程別定義を重複登録しない。
- 対象教育課程の科目一覧を投入する。テスト学生の成績記録がない科目も一覧に表示できるようにする。
- 必修科目の単位合計、選択必修群の必要単位合計が本書の16・21・21、14・18・15と一致することを投入時に検証する。

## 10. 非機能要件

| ID | 分野 | 要件 |
|---|---|---|
| N01 | 認証・認可 | 学生情報と成績情報の取得はサーバー側で認証を検証する |
| N02 | 学生間の分離 | リクエストで他人の学生IDを指定されても閲覧できない。ログイン情報から本人を特定する |
| N03 | パスワード | 平文保存せず、パスワード保存用の方式でハッシュ化する |
| N04 | セッション | ログアウト・有効期限切れで認証を無効化する。具体的な方式・期限は基本設計で定める |
| N05 | 閲覧専用 | UIだけでなくサーバー側でも、学生による成績・科目・卒業要件の変更を許可しない |
| N06 | 入力・表示 | パラメータ化クエリ等でSQLインジェクションを防ぎ、表示時の文字列を適切に処理する |
| N07 | 通信 | 公開環境ではHTTPSを使用し、秘密情報をソースコードへ直接記載しない |
| N08 | 視認性 | 色だけで取得状態・達成状況を表現せず、文字ラベルを併記する |
| N09 | 操作性 | 読み込み中、空状態、失敗状態を表示し、キーボードでも基本操作できるようにする |
| N10 | 表示環境 | PCの現行主要ブラウザを主対象とする。画面幅が狭い場合も表を横スクロール等で閲覧できる |
| N11 | 整合した表示 | 1回の画面取得で、総単位数・各条件の集計に同じ成績データを使用する |
| N12 | 保守性 | 判定処理と表示処理を分離し、配色・科目・必要単位数を変更しやすくする |
| N13 | 再現性 | データベース初期化とシード投入によって同じテスト環境を再構築できる |

同時利用者数、応答時間、稼働率の数値目標は未設定とする。今回の開発規模に合った具体値を、必要に応じて基本設計で決定する。

## 11. エラー処理

| 状況 | 表示・動作 |
|---|---|
| 認証失敗 | 入力情報が正しくないことを表示し、ログインを成立させない |
| 未認証・セッション期限切れ | 学生データを返さず、再ログインへ案内する |
| 他学生の情報へのアクセス | データを返さず、アクセスを拒否する |
| 成績記録なし | 有効な学生・カリキュラムで成績0件なら、取得0単位・対象科目は未取得として表示する |
| 学生の所属・カリキュラム不明 | 判定不能として表示し、達成・未達成を確定しない |
| 科目・卒業要件マスタ不足 | 判定不能として表示し、不正確な数値を確定表示しない |
| 通信・DB接続失敗 | 取得に失敗したことと再試行方法を表示する |

エラー時にパスワード、接続情報、SQLの詳細、他学生の個人情報を画面へ表示しない。

## 12. テストデータと受入条件

### 12.1 テスト学生

少なくとも以下の5パターンのテスト学生を用意する。超過換算・境界条件の検証は追加データまたはテスト用シードで行う。

| 学生 | データの状態 | 確認すること |
|---|---|---|
| A | 総単位数・各区分が不足 | 基本的な取得・不足単位計算 |
| B | 総取得124単位以上、必修科目が不足 | 総単位達成でも全体は未達成になる |
| C | 全ての対象単位要件を達成 | 全体が達成になる |
| D | 総単位数を確保し、一部の選択必修群が不足 | 他の群の余剰で不足を補わない |
| E | 履修中・不合格・再履修履歴がある | 合格済み科目だけを重複なく集計する |

### 12.2 受入条件

| ID | 条件 | 期待結果 |
|---|---|---|
| T01 | 正しい学籍番号とパスワードでログイン | 本人のダッシュボードを表示する |
| T02 | 誤った認証情報、ログアウト後のアクセス | 認証が成立せず、学生データを閲覧できない |
| T03 | 別の学生IDを指定して情報取得を試みる | 他学生の情報を取得できない |
| T04 | 学生から成績変更を試みる | UIに操作がなく、サーバー側でも変更を拒否する |
| T05 | 取得済みと未取得が混在 | 表示ラベルと背景色が正しく、未取得科目も一覧に存在する |
| T06 | 総取得123単位と124単位 | 総不足がそれぞれ1単位と0単位になる |
| T07 | 総取得124単位以上で必修不足 | 総不足0単位でも全体は未達成になり、未取得必修名を表示する |
| T08 | 総合等の群で10単位以上、人文0単位または社会0単位 | 群の単位数条件と内訳条件を別に表示し、全体は未達成になる |
| T09 | 外国語の選択必修4単位、必要2単位 | 超過2単位が実学基礎の選択へ換算され、総取得は4単位のままとなる |
| T10 | 大分類または選択必修群の一部だけに余剰 | 別の大分類・別の選択必修群の不足へ充当しない |
| T11 | 同じ科目に不合格・合格の記録がある | 科目単位を1回のみ算入する |
| T12 | 124単位以上で全条件達成 | 卒業単位要件を達成と表示する |
| T13 | シードで成績を更新後に画面を再取得 | 更新後の成績で全体・カテゴリ別表示を再計算する |
| T14 | 有効なマスタがある学生の成績0件 | 取得0単位と表示し、正常な未取得状態として扱う |
| T15 | マスタ不足・DB接続失敗 | 判定不能・取得失敗を表示し、達成と誤表示しない |
| T16 | 人工知能コースのコア科目・専門演習 | コース別の選択必修種別を使用し、他コース固有科目を選択として扱う |

## 13. 基本設計で確定する事項

業務範囲と卒業単位判定ルールは本書を基準とする。以下の実装上の詳細は基本設計で確定する。

| 項目 | 方針・現状 |
|---|---|
| 技術構成 | HTML・CSS・JavaScriptを用いたWeb画面と、RDBに接続するサーバーを構成する。具体的なフレームワーク・DB製品は未決定 |
| DB物理設計 | 第9章の論理データ要件から、テーブル、型、制約、索引を定める |

これらの決定によって、学生による編集不可、対象課程、単位計算、初期開発の除外範囲を変更しない。業務ルールを変更する場合は、本書の版を更新する。

## 14. 初期開発の完了条件

対象教育課程の科目・卒業要件マスタと複数のテスト学生を投入し、ログイン、本人情報の取得、ダッシュボード、科目一覧、卒業単位要件の判定を実装する。第12章の受入条件を満たし、再現可能な初期データ投入手順を用意した時点で初期開発を完了とする。
