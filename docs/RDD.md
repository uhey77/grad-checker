# 卒業要件チェッカー 要件定義書

| 項目 | 内容 |
|---|---|
| 文書版 | 1.3（技術構成・判定履歴・本人入力確定版） |
| 更新日 | 2026年10月10日 |
| 対象 | 添付の2026年度学生便覧に載る全学部・学科・専攻・コースの学部課程 |
| 目的 | 学生が自身の成績を入力・保存し、所属課程の卒業単位要件と不足条件を確認できるようにする |
| 根拠資料 | 東京工科大学2026年度学生便覧。各課程の教育課程表、卒業要件、履修細則 |

## 1. 背景と目的

学生が自分の所属と成績を登録し、卒業に必要な単位数、修得単位数、卒業要件への算入単位数、不足単位数、未修得必修科目を確認できる独立したWebアプリケーションとする。実際の大学成績システムやCampus Squareには接続しない。入力は学生の自己申告であり、大学が登録した公式成績の照会ではない。

人工知能コースだけに固定せず、選択した所属課程に応じた科目と要件を使用する。科目区分・科目群と、所属する専攻・コースを区別して表示する。不足条件の単純合計を「卒業まで残り何単位」と表示しない。

### 1.1 技術構成

旧ルート文書の構成を統合し、2026-10-11の設計変更でGoを外部HTTP、Pythonを業務処理・DBとして共通の層構成に配置する。
現時点の実装対象は開発用科目一覧。詳細は[バックエンドの構成](backend_architecture.md)を参照する。

| 分野 | 採用技術 |
|---|---|
| バックエンド | Go（外部HTTP） / Python（業務処理） / FastAPI（内部通信） / SQLModel / SQLite |
| フロントエンド | React / TypeScript（Viteで開発・ビルド） |
| テスト | pytest / Goのtesting |
| 通信 | JSON |
| APIドキュメント | 外部APIのOpenAPI / Swagger UI（今後整備） |

授業第2回資料の59枚目では、データ入出力・DB保存・JSON等の通信・HTML表示・JavaScriptによる動的生成・CSS装飾を求める。学生向けJSONファイルの読み込みは課題の必須条件ではない。APIのJSON通信と、開発用のJSONシードを使う。

## 2. 開発範囲と前提

### 2.1 初期開発の範囲

| 項目 | 要件 |
|---|---|
| 対象課程 | 添付便覧に載る全学部・学科・専攻・コース。大学院は対象外 |
| 適用カリキュラム | 所属課程に対応する、便覧で確認したカリキュラムを明示して使用する |
| 認証 | ログインを必須とし、本人の所属・成績を保存する |
| 学生の操作 | 本人の所属課程の選択、成績の入力・保存・訂正・入力取消、判定結果の閲覧 |
| 科目の選択 | 自学部および対象となる他学部・他学科の科目一覧から選ぶ |
| マスタ管理 | 開発者が公式資料に基づき科目・分類・要件・算入規則を登録する |
| 判定対象 | 授業科目の修得と単位に関する卒業要件 |
| 表示 | 所属、科目区分、科目群、種別、科目単位、成績、条件別の必要・修得・算入・不足単位 |
| データベース | アカウント、本人成績、課程別マスタを分離してRDBで保存する |

便覧に記載のある全学部課程を対象とすることと、全課程のマスタが既に完成していることは別である。未整備の課程を対応済みと表示しない。課程によって学科・専攻・コースの有無が異なるため、存在しない所属階層を必須入力にしない。

入学年度別の適用範囲は便覧の規定と照合する。2026年度の便覧を参照したことだけを理由に、すべての入学年度へ同一ルールを適用しない。対応できるカリキュラムの範囲はマスタの整備時に明示する。

### 2.2 初期開発に含めない機能

- 実際のCampus Square・大学成績システムとの連携、大学アカウントとのSSO。
- 履修登録・取消手続、大学の公式成績の変更。
- 学生による科目マスタ・単位数・卒業要件・算入規則の変更。
- 進級、卒業課題着手、早期卒業、GPAによる履修可否の判定。
- 在学年数や教授会・学長による正式な卒業認定の判定。
- 大学院の修了要件。
- 判定結果の他人への共有・公開URL。
- 学生向けの成績JSONファイル読み込み・エクスポート（後回し）。
- 学生便覧の自動取得・自動解析更新。添付PDFを根拠にマスタを整備する。

本人の入力取消はアプリ内の自己申告成績を取り消す操作であり、大学の履修取消ではない。放送大学・他大学・資格等による認定、特殊な読み替えは、今回確定した本学他学部科目の対応と分け、対応範囲を未確定事項で管理する。

### 2.3 未決の追加機能

アカウントの自己登録・発行方法とパスワード再発行は未決定。学生向け成績JSONファイル入出力は将来候補とする。おすすめ科目はまず不足条件と開講学期に基づくルールで提示し、学習モデルによる推薦は将来検討する。判定履歴の本人専用保存・再取得は初期開発に含める。

## 3. 利用者と基本利用フロー

1. 学生がログインする。
2. 本人の学部・学科・専攻・コースおよび適用カリキュラムを選択・確認する。
3. 科目一覧から修得した科目等を選び、成績を入力して保存する。
4. システムが所属課程の科目種別、分類、他学部科目の算入先・上限を適用して判定する。
5. 学生がチェックを実行すると、その時点の入力・課程・規則版・判定結果・おすすめ科目を保存する。達成状況と不足条件を確認し、過去の判定結果も本人だけが再取得できる。
6. 次回ログイン時に保存した成績を取得し、追加・訂正・入力取消を行う。

本人データはサーバー側で認証に基づき特定する。他人のデータは閲覧・変更できない。学生に科目単位数、換算先、上限値の自由入力を求めない。所属変更時も既存の成績を黙って削除せず、適用可能性と再計算への影響を確認する。

## 4. 用語

| 用語 | 定義 |
|---|---|
| 所属課程 | 学部・学科・専攻・コースの組合せ。存在する階層のみ使用する |
| 科目区分 | 実学基礎科目、専門基礎教育科目、専門教育科目など、各課程の分類 |
| 科目群・小分類 | 科目区分の内側の分類。公式資料にある階層と名称を使用する |
| 種別 | 所属課程における必修、選択必修、選択等 |
| 修得単位数 | 合格した科目の実単位を、同一科目の重複を除いて数えた値 |
| 卒業要件への算入単位数 | 算入対象・上限・配分規則を適用して、その要件に数える単位数 |
| 不足単位数 | 必要単位数から算入単位数を引き、0未満を0とした値 |
| 達成／未達成 | APIの `pass / fail` に対応。本システムが対応する授業・単位要件を満たす／満たさない状態 |

他学部科目の上限超過分などがある場合、修得単位数と卒業要件への算入単位数は異なる。科目を開講する学部の分類と、学生の所属課程での算入先も区別する。

## 6. 卒業単位要件と根拠資料

### 6.1 課程別マスタ

すべての対象課程について、教育課程表・卒業要件・算入細則を照合し、必要単位数、必修科目集合、選択必修群、内訳条件、分類、換算・上限規則をマスタ化する。同名科目でも所属課程によって種別が異なる場合は、課程別に定義する。

確認した規定には資料名、冊子ページ、適用課程、適用年度、確認状態を記録する。未確認の数値を仮の確定値として投入しない。

### 6.2 確認済みの例：コンピュータサイエンス学部

便覧の冊子94ページ（PDF96ページ）で次の数値を確認済みである。この表は課程別の例であり、全学部共通の要件ではない。

| 専攻 | 必修 | 選択必修 | 選択算入 | 総必要単位 |
|---|---:|---:|---:|---:|
| 先進情報専攻 | 58 | 47 | 19以上 | 124以上 |
| 社会情報専攻 | 55 | 50 | 19以上 | 124以上 |

両専攻とも科目区分別の合計は実学基礎38以上、専門基礎42以上、専門教育44以上。選択の最低値はそれぞれ8・3・8単位である。選択必修群の内訳とコース別対象科目は各専攻・コースの教育課程表を使用する。先進情報専攻には情報基盤・人間情報・人工知能の3コースがある（冊子83ページ）。

### 6.3 他学部・他学科の科目

冊子53ページの「履修要項（4学部共通）」では、応用生物・コンピュータサイエンス・メディア・工学の4学部について、同じキャンパスの他学部・他学科の専門基礎教育科目・専門教育科目のうち、選択または選択必修の講義科目を対象とし、演習・実習・実験を除く。対象となる修得単位を合計6単位まで算入し、超過分は自由科目とする。

専門基礎教育科目は所属課程の専門基礎教育科目の選択へ、専門教育科目は所属課程の専門教育科目の選択へ算入する。6単位の上限は科目区分ごとではなく、対象他学部科目の合計に適用する。対象科目8単位を修得しても、卒業要件への算入は最大6単位である。

この4学部共通規則を他学部へ無条件に流用しない。他課程の規則と、上限を超えた際に複数の算入先へ配分する順序は、資料確認後に定義する。未確認の配分を任意に決めて達成判定しない。

## 7. 集計・判定ルール

1. 所属課程・カリキュラムと対象科目・要件・算入規則を取得し、整合性を確認する。
2. 成績から修得状態を導出する。冊子61ページで確認したS/A/B/Cは合格、Dは不合格、Xは未受験による不合格である。未確定と未履修はデータ状態として区別する。入力可能な成績記号はS/A/B/C/D/Xとする。認定R等は初期の学生入力では受け付けず、認定対応は別途要件を確認する。
3. 同一科目は修得単位に1回だけ算入する。不合格後に合格した科目は修得済みとし、再履修で重複加算しない。
4. 課程別の必修科目、選択必修群、内訳条件を個別に判定する。別群の余剰で不足を補わない。
5. 所属課程で許される選択必修超過分の換算を適用する。CS学部の冊子94ページ注1では、超過分を同じ科目区分の選択へ換算する。換算分を実際の修得単位へ二重加算しない。
6. 他学部科目は対象・算入先・合計上限を適用し、非算入分とその理由を表示する。修得したことと卒業要件に数えられることを分ける。
7. 総不足は `max(総必要単位 - 総算入単位, 0)`、条件別不足は `max(条件の必要単位 - 条件への算入単位, 0)` とする。総不足には上限等を適用した総算入単位を使い、自由科目を無条件に含めない。
8. 全ての対象単位条件・必修条件を満たした場合だけ達成とする。総不足0でも必修・内訳不足があれば未達成とする。
9. 親条件・子条件・科目区分別不足を単純加算しない。全科目未入力は修得・算入0単位の正常な未達成として扱う。
10. マスタ不足・不整合・未確認の算入規則に依存する場合、成功結果に第3の状態を返さず、理由付きの設定・算入規則エラーとして扱う。未確定値を0や非算入と推測せず、全体の確定判定を出さない。
11. ダッシュボードのGETは最新の保存済み成績から計算するだけで、判定履歴を増やさない。POSTによるチェック実行時だけスナップショットを保存する。判定がエラーなら成功履歴は作らない。
12. おすすめは未修得科目の候補提示であり、履修許可・時間割の適合・将来の開講・推薦だけでの卒業達成を保証しない。未知の算入規則を使って候補を確定しない。

例：外国語の選択必修を4単位修得し、必要2単位であれば、超過2単位を実学基礎の選択へ換算する。直接修得した選択6単位と合わせて選択算入8単位となる。実際の修得単位は外国語4＋直接選択6＝10単位のままである。

表示は「卒業単位要件の達成状況」とし、「自己入力した成績と、本システムが対応する単位要件に基づく結果です」と説明する。正式な卒業認定や大学による成績確認済みであるかのような表示をしない。

## 8. 画面要件

### S00 ログイン

認証情報を入力してログイン・ログアウトできる。自己登録か事前発行かは未決定であり、アカウント作成画面を必須と決めない。

### S01 ダッシュボード・所属選択

所属課程と適用カリキュラムを選択・確認し、総必要・修得・算入・不足単位、全体と科目区分別の達成概要を表示する。存在しない専攻・コースは選択を求めない。所属変更時の保存成績への影響を案内する。

### S02 成績入力・科目一覧

科目名、開講元、科目区分・科目群・種別・単位数、開講学期、本人の成績・修得状況を表示する。自学部・他学部の科目を科目区分・学部／学科・学期で絞り込み、検索して選択し、成績を入力・訂正・取り消して保存できる。科目単位数・算入規則は編集できない。

未入力科目は未履修と表示する。保存中・保存成功・保存失敗・未保存変更を区別し、保存失敗で入力が消えたり保存済みと表示されたりしない。サーバーに保存されていない変更を確定判定へ混在させない。

### S03 卒業要件詳細

条件別の必要・修得・算入・不足単位と達成／未達成を表示する。未修得必修科目、選択必修超過換算、他学部科目の算入先・算入上限・上限超過分の内訳を表示する。実単位と算入値を区別する。おすすめ科目と推薦理由、チェック実行、本人の判定履歴一覧・詳細を同画面内に配置する。過去の詳細には判定日時・当時の課程・規則版を表示し、最新の判定と区別する。共有ボタンは設けない。

### 共通状態と更新

認証後はS01を表示し、S01〜S03を共通ナビゲーションで相互に移動できる。色だけで状態を示さず文字を併記する。読み込み、正常な成績0件、取得・保存失敗、設定・算入規則エラーを区別する。設定エラー時は理由と対象科目・条件を表示し、確定結果のように見せない。PCを主対象とし、狭い画面では表の横スクロールに対応する。保存後と再取得時に再計算し、自動ポーリングは必須にしない。

| 算入規則 | 学生の課程、対象科目集合、算入先、共通上限、超過換算、適用条件、根拠 |
| 判定結果 | UUID、本人ID、入力JSON、結果JSON、課程・規則版、成績版、作成日時 |

他学部の成績を保存できるよう、科目の存在を本人カリキュラム内の科目だけに限定する旧制約は使用しない。ただし、既知の科目・有効な算入規則への参照は検証する。同名科目を名前だけで同一視しない。成績・所属は本人が更新でき、マスタは学生から更新できない。修得状態・算入値は入力フラグではなく成績と規則から導出する。

判定結果の入力・結果はスナップショットとして保存する。科目名・分類・必要値・推薦理由等も当時の表示情報を含め、現在のマスタ変更で過去の表示が変わらないようにする。公開共有の構造は作らない。科目単位数は正の整数、必要単位・上限は規則に応じた非負整数とする。

## 10. 非機能要件

- 本人以外の成績・所属をサーバー側で閲覧・変更できないようにする。
- パスワードは平文保存せず、認証期限・ログアウトでセッションを無効化する。
- 成績更新は認証・入力検証を行い、セッション方式に応じたCSRF対策を適用する。
- 科目・要件・規則マスタの編集権限を学生へ与えない。
- 1回の判定に同一の保存済み成績・規則の版を使用する。
- シードによる再現可能なマスタ投入と、課程別の網羅・整合性検証を用意する。
- 公開時はHTTPSを使用し、秘密情報をソースへ直接記載しない。
- 色だけに依存しない表示と基本的なキーボード操作に対応する。

- 判定ルールはpytestのユニットテストで検証し、本人認可・保存・再取得を結合テストで確認する。
- APIドキュメントをSwagger UIで自動生成し、READMEに起動・DB初期化・シード投入・テストの手順を記載する。
- JSONシードを同梱し、コマンド1つで同じ初期マスタを再現する。学生向けファイル読み込みとは別の処理とする。
- 科目数200件程度の条件で判定APIが1秒以内に応答する。全課程データ・他学部科目・履歴増加時の性能は別途測定する。
- GitHubでソースを管理する。開発期間は2週間を目安とし、日別の詳細スケジュールは記載しない。

## 11. エラー処理

| 状況 | 動作 |
|---|---|
| 未認証・認証失敗・期限切れ | 本人データを返さず、ログインを案内する |
| 他人のデータを指定 | 閲覧・変更を拒否する |
| 正常な成績0件 | 修得・算入0単位、未履修、未達成として表示する |
| 不正な成績・未知の科目 | 保存を拒否し、修正箇所を示す |
| マスタ不足・未確認規則 | 設定・算入規則エラー。影響する全体の確定判定を出さない |
| 通信・DB接続・保存失敗 | 再試行を案内し、保存完了や達成と誤表示しない |

APIエラーは `{"detail": "日本語のメッセージ"}` に統一し、画面はdetailの文字列を表示する。入力検証エラーも日本語のメッセージへ正規化する。パスワード、接続情報、SQL詳細、他人の個人情報をエラー表示へ含めない。

## 12. 受入条件

| ID | 条件 | 期待結果 |
|---|---|---|
| T01 | ログイン・再ログイン | 本人の所属と保存した成績を取得できる |
| T02 | 誤認証・ログアウト・期限切れ | 本人データへアクセスできない |
| T03 | 他人の成績の取得・更新・取消 | すべて拒否する |
| T04 | 本人成績の追加・訂正・取消 | 保存され、再取得・再計算へ反映する |
| T05 | 学生が単位・要件・算入規則を変更 | 拒否する |
| T06 | 複数の学部・専攻・コースを選択 | 各課程の科目・種別・必要単位を使用する |
| T07 | 総不足0だが必修・内訳不足 | 未達成で、不足条件を表示する |
| T08 | 選択必修の超過換算 | 公式規則に従って配分し、総単位へ二重加算しない |
| T09 | 4学部共通の対象他学部科目8単位 | 算入は合計最大6、超過2は非算入と表示する |
| T10 | 他学部の対象外科目・分類の異なる科目 | 対象判定と課程別算入先を適用し、自学部の必修を勝手に補わない |
| T11 | 再履修・複数合格 | 同一科目は1回だけ数える |
| T12 | 全対象条件を達成 | 達成を表示する |
| T13 | 成績0件 | 正常な0単位・未達成として扱う |
| T14 | マスタ不足・未確認の配分規則 | エラーを表示し、達成／未達成の確定結果を返さない |
| T15 | 保存失敗・未保存変更 | 入力を保持し、保存済みや確定結果へ混在させない |
| T16 | 所属変更 | 成績を黙って削除せず、新課程での適用・再計算を確認する |
| T17 | 全対象課程のマスタ照合 | 便覧の科目、必要値、分類、算入細則との対応を記録する |
| T18 | 判定後に成績・マスタを変更し過去結果を取得 | 保存した入力・結果・日時・規則版・おすすめを当時のまま返す |
| T19 | 他人の判定IDや未認証で履歴取得 | 結果を返さない。公開共有経路がない |
| T20 | 不足条件がある | 算入対象の未修得候補と推薦理由を表示する |
| T21 | 科目区分・学部／学科・学期を併用 | 指定条件に一致する科目を表示する |
| T22 | 小数・0・負数の科目単位、未知科目、不正成績 | 入力・シード検証で拒否し、日本語メッセージを返す |
| T23 | 正常な判定・設定エラー | 成功判定はpass/failのみ。エラーをfailへ読み替えない |
| T24 | 200科目程度の判定、初期化、文書 | 1秒以内、JSONシードで再現、pytest・Swagger UI・README手順を確認する |
