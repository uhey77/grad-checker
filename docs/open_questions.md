# 未確定事項と確認記録

## 1. 原則

公式仕様、MVPの範囲、実装上の提案を分けて管理する。未確認の大学ルールを独自に確定しない。根拠はユーザーが追加した[2026年度学生便覧](2026hcgakuseibinran.pdf)。冊子ページとPDFページの差は+2。確認日は2026年10月9日。

## 2. 確認一覧

| ID・状態 | 事項 | 影響 | 確認が必要な理由・根拠 | 暫定対応・次の作業 | 実装前の解決 |
|---|---|---|---|---|---|
| Q01 解決済み | S/A/B/C/D/Xの意味・算入 | S02、全判定 | 冊子61（PDF63）でS/A/B/C/Rは合格、Dは不合格、Xは未受験による不合格と確認 | S/A/B/C算入、D/X非算入を正式な根拠付き仕様として反映。未確定/未履修は本システム状態 | 解決済み |
| Q02 未解決 | 総合等10単位を超え、人文または社会の内訳が不足する場合の超過換算 | 実学基礎の選択算入、S01/S03、全体判定 | 冊子85、86、94は10・人文2・社会2と同区分超過換算を示すが、内訳未達成時の配分を明示しない | 超過候補は算出。当該換算・依存する選択算入をnull、全体indeterminateとする。超過0なら換算0、内訳未達成のためunmet。学務担当に具体例（総合等12・人文0・社会2）で確認 | 通常ケースの実装は可能。このケースを確定判定する前に必須 |

| Q05 未決定 | DB製品・実行構成・公開経路・バックアップ | 物理設計、スナップショット読取、Cookie/CORS | バックエンド環境はFastAPI/SQLModel、フロントはViteだがDBと配備方式は未指定 | 論理型と制約は本設計を使用。同一オリジンの開発/公開プロキシを提案。DB選定後に複合FK・CHECK・読取一貫性・接続管理を確定 | DB/認証接続の実装前に必須 |
| Q06 未決定 | 公式学籍番号書式・科目コード・学期コード | 入力検証、マスタ、履歴表示 | 便覧の教育課程表は科目名・単位・種別を示すが、模擬学務の正式コード体系は未提供 | 学籍番号はASCII英数字1〜32文字、科目は内部安定IDと説明用コード、学期はfirst/second/full_year/other。正式コードとして偽装しない。テスト用対応表を次フェーズで確定 | 模擬シード作成前に必須。実学務連携はMVP外 |
| Q07 対象外として確定 | R（認定）、外部単位、取消・特殊な読み替え | 入力データ、全判定 | 冊子61でRは認定による合格。ただしMVPは特殊な単位認定を含めない | RをDに読み替えず投入拒否・検出時判定不能。取消は通常履歴の追加で表現しない。対応追加時はRDDから改訂 | MVP対象外。実装前の追加承認は不要 |
| Q08 暫定デザイン値 | 修得済み行の配色・画面画像の一致 | S02、UI確認 | 既存PNGは更新前の参考。配色は公式ルールではない | 本文の4画面・ラベル優先。淡い緑+文字の暫定値を使用し、実装時にコントラスト・幅を検証 | 初期実装可能。受入前に確認 |

Q02は大学のルール未確定、Q04〜Q06は開発上の選択、Q03は根拠確認済み値のデータ化作業である。これらを一括して「公式仕様未確認」と扱わない。

## 4. 設計書間の確認結果

| 観点 | 対応・確認対象 |
|---|---|
| 画面数 | RDDと画面設計をS00〜S03の4画面に統一 |
| 成績 | 確認済みS/A/B/C算入、D/X非算入、未確定/未履修区別、R対象外を全資料に反映 |
| 必要値 | 判定20コードの必要値とAPIの20条件、テスト基準124・大分類38/42/44を対応 |
| 換算 | 総実単位への追加禁止、同一大分類のみ、Q02のnullとindeterminateをRDD/API/テストに反映 |
| データ | 全科目は課程別定義起点、代表履歴から成績・年度・学期を生成、派生値は判定関数から返す |
| 権限・範囲 | 本人専用/me、成績更新・管理者画面・履歴詳細・入学年度分岐はMVPに追加しない |

作業時に7文書を機械確認し、JSON例10件のパース、Mermaid図3件の構文解析（Mermaid 12.1.0）、ローカル参照リンク44件の存在、要件20コードとAPIの必要値一致、選択必修8群の配分、58+47+19=124および大分類38/42/44の計算一致を確認した。旧用語の残存とgit diffの空白エラーも確認した。検証用ツールは一時ディレクトリに置き、アプリ依存関係は変更していない。アプリケーションの動作試験やシード網羅検証は実装フェーズに残る。

## 5. 実装開始前の順序

1. Q05のDB・接続構成、Q04の認証設定方針、Q06の模擬コード体系を確定する。
2. Q03の全科目マスタとテスト学生・成績フィクスチャを設計し、便覧の転記を照合する。
3. Q02を確認する。解決まで判定不能の仕様を維持し、換算値を独自に確定しない。
4. DB制約・セッション・判定関数・API・4画面を実装し、テスト仕様の各IDで検証する。
