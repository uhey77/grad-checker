# 基本設計の変更記録（v1.2〜v1.3）

更新日：2026年10月10日。ファイル名は既存リンクのため維持する。[RDD](RDD.md) v1.3が現在の基準。本書は変更記録であり、機能の実装済み報告ではない。

## 1. 会話で確定した仕様

| 項目 | 現在の仕様 |
|---|---|
| 対象 | 添付便覧に載る全学部・学科・専攻・コースの学部課程 |
| スタック | Python/FastAPI/SQLModel/SQLite、React/TypeScript、pytest |
| 入力 | ログインした本人が所属・成績を入力・保存・訂正・取消 |
| 科目マスタ | 事前投入した既知科目を選択。現在のDB・シードは未実装 |
| 科目表示 | 開講元、区分、科目群、種別、科目単位、開講学期 |
| 絞り込み | 科目区分・学部／学科・学期 |
| 数値 | 科目単位は正整数。実修得と卒業算入を区別 |
| 成績・判定 | 成績S/A/B/C/D/X、未確定・未履修は状態。判定はpass/fail |
| 算入 | 課程別の選択必修超過換算と他学部対象・算入先・共通上限 |
| 保存 | 成績保存に加え、判定実行時の入力・結果・推薦・版を保存し本人だけ再取得 |
| 共有 | 不要。公開URL・第三者閲覧は作らない |
| 推薦 | 不足条件に基づく候補、必修優先・開講学期順。学習モデルは将来検討 |
| JSONファイル | 学生向け読み込み・エクスポートは後回し。API通信とJSONシードは使用 |
| エラー | 日本語detail文字列を画面表示。設定不足を成功判定へ変換しない |
| API | /api、現時点でv1なし。最新表示と判定履歴を分離し、共通判定関数を利用 |
| 非機能 | 200科目で判定API1秒以内、Swagger UI、README手順、pytest、JSONシード |
| 期間 | 2週間の目安のみ。日別スケジュールは省略 |
| 便覧 | 添付PDFを根拠に手動確認・マスタ整備。自動取得は追加しない |

## 2. 旧ルートrdd.mdからの統合

技術・テスト・起動・ドキュメント・性能はルートの指定を採用。判定結果保存・再取得、おすすめ科目も引き継ぐ。認証・全課程対応・他学部算入・本人の保存成績は会話で変更した要件。結果共有は不要と決定し、学生向けJSONファイル入出力は後回しにした。

ルートの学生向け科目登録・一括登録APIに代わり、既知科目の事前登録と開発者のJSONシードCLIを使用する。成績保存、GETでの最新判定、POSTでの判定履歴保存を分離する。元のルート文書は2026年10月11日に削除し、現在の要件をdocs/RDD.mdへ集約した。

## 3. 整合した基本設計

- [判定](graduation_requirement_logic.md)：課程別条件、算入、推薦、pass/failとエラー、共通関数。
- [DB](database_design.md)：SQLiteの整数制約、本人成績の更新、他学部科目参照、check_resultsの不変スナップショット。
- [API](api_specification.md)：/api、本人更新と所有権、版競合、detail、最新表示と履歴取得。
- [画面](screen_design/student_screen_design.md)：本人入力・保存状態・フィルタ・最新／過去・おすすめ。
- [テスト](test_specification.md)：pytest、受入T01〜T24、本人更新、他人拒否、履歴不変、整数・性能検証。

旧v1.1の人工知能固定・閲覧専用・成功応答の第3状態・更新拒否テストを現行仕様から除いた。既存PNGは旧参考であり今回は更新していない。
