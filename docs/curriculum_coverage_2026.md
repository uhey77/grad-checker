# 2026年度の全学部・大学院マスタと対応状況

2026年10月19日、Issue #46・#48。対象は東京工科大学の八王子・蒲田両キャンパス。
大学公式の[教育課程表一覧](https://www.teu.ac.jp/koukai/19430/019432-2.html)、
[学部卒業要件](https://www.teu.ac.jp/ap_page/koukai/sotsugyoyoken_2026_3-4-1.pdf)、
[大学院修了要件](https://www.teu.ac.jp/ap_page/koukai/grad_sotsugyoyoken_2026_3-4-2.pdf)を基準にする。
大学・大学院の[構成一覧](https://www.teu.ac.jp/gakubu/index.html)とも照合した。

学部25課程（看護の2経路を区別）、大学院13課程（修士6・博士後期4・英語プログラム3）を登録する。
確認済みの単位条件を評価できる範囲は学部22・修士6の計28課程。
残る10課程は理由を表示してAPI409で停止する。登録済みを全課程の判定対応完了と扱わない。
修士の単位以外の条件は本人申告であり、大学による正式な修了認定ではない。

## 適用年度と出典

`HANDBOOK-2026` は2026年度に公開された資料を使用するという識別子で、2026年度入学生限定を意味しない。
科目表の本文には2024年度以降、2025年度以降、2024年度入学生用、年度表示なしが混在する。
卒業要件表の2026年度入学生用という表記だけを科目集合へ自動伝播しない。
すべての `admission_year_from/to` は未確認のnullを保持し、確認状態はunverified。
従来のCSと同様、2026年度資料を本人が選択した基準として使うが、入学年度への適用確認済みとは表示しない。

`backend/seeds/university_2026.source.json` は16個の公式PDFについてURL、SHA-256、ページごとの原セル・本文を保持する。
同ファイルからオフラインでシードを再生成する。アプリに便覧の自動取得・自動更新は追加しない。
結合セル、脚注、クォーター列、科目表と要件表の不一致も原資料に残す。
原本PDFはリポジトリへ追加しない。既存CSの原本SHA-256と転記は従来のsource.jsonを維持する。

## 算入と修了判定

学部は既存の卒業単位判定を使用する。科目の同一性は公式表内の同じ行で共有し、学部が異なる同名科目は統合しない。
分類の親子、必修集合、選択必修群、人文・社会の内訳、選択最低、区分小計を保持する。言語聴覚学専攻の専門基礎共通・専門発展の選択は、`credit_minimums`の一つの合計3単位条件とし、総単位へ重複加算しない。
所定単位を超えた選択必修は公式表の注記に従い同区分の選択へ換算する。

八王子4学部共通の他学部・他学科算入は、従来の便覧冊子53/PDF55の6単位共通上限を使用する。
新しい明示的な対応表は、純粋な講義で、関係するどのコースでも必修ではなく、専門基礎／専門教育の分類が一意な科目に限定する。
コースにより必修に変わる科目は、課程外での扱いの確認が終わるまで対象外とし、修得済みなら未登録理由で判定を停止する。
工学部では専門基礎が専門教育区分内にあるため、算入先も専門教育の選択とする。
合計上限を区分ごとに重複適用しない。取得順・同時期は要件充足を優先する既存のアプリ方針と注意表示を維持する。
蒲田の他学部算入、大学院の他研究科認定、資格・他大学認定へ同じ6単位規則を流用しない。

大学院は `completion_policies` の独立した単位区分で評価する。
バイオ・情報メディア修士は専門14・ジェネリックスキル2・必修研究14、工学修士は総合4・専門12・必修研究14。
バイオ・情報メディアのジェネリックスキル超過は修了単位に算入せず、工学の総合科目超過は専門科目へ換算する。
デザイン修士は必修26・選択4、医療技術修士は基礎12（必修8を含む）・領域特論2・領域演習2・必修研究14。
必修研究科目が不足していれば、他の選択科目を多く修得しても補わない。
博士後期へ修士の30単位や学部の124単位を流用しない。

在学期間、研究指導、論文・作品審査、最終試験、必要な課程での対外発表は、公式条件ごとに本人が達成／未達成／未確認を入力する。
条件が一つでも未確認なら全体はpending（判定保留）。回答済みで不足があればfail、単位・必修・非単位条件をすべて満たせばpass。
全結果を本人申告に基づく参考判定として表示する。単位だけの条件は従来どおりpass/failでありpendingにはしない。
申告内容・条件名・根拠・結果は判定履歴に保存し、後のマスタ変更で再計算しない。
本人の既存の成績版・所属版を照合し、他人の履歴は取得できない。

## 再生成と投入

検証には `DATABASE_URL=sqlite:////private/tmp/grad-checker-all-test.db` のような専用DBを使う。
通常の開発DBは検証のために変更しない。

```sh
task backend-all-seed-build
task backend-all-seed
# Makeでも同名のターゲットを使用できる
```

投入順は既存CS科目、既存CS要件、追加全課程科目、追加全課程要件。
追加シードには既存CS規則に対応する他学部の対象行が含まれるため、この順を守る。
各CLI呼出しは全件成功か全件取消。同じシードの再投入は0件追加、異なる内容の既存IDは拒否する。
省略した既存行は消さず、起動時はテーブルだけを追加してマスタを自動投入しない。

## 確認方法

`test_university_curricula.py` が公式固定値、全登録範囲、照合済み学部の空・全修得、修士6課程の保留・達成・未達成、必修研究不足、区分別超過、未確認課程の停止、回答の重複・型、オフライン再生成一致を検証する。
`test_university_http.py` はシード投入・再投入、所属・成績保存、Goからの修了判定、本人申告を含む不変履歴、成績版の競合、CSRF、他人の取得拒否を実Go→Python→一時SQLiteで検証する。
全課程を読み直す代わりに、判定時は本人課程・明示的な算入対象・本人が入力した科目のみを同一トランザクションで取得する。
画面は未整備の課程と根拠を表示し、修士の非単位条件入力、判定保留・本人申告表示、履歴再取得を確認する。
