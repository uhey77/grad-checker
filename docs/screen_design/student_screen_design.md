# 学生向け画面設計

文書版：1.4（2026年10月15日更新）。[RDD](../RDD.md)を基準とし、React / TypeScript / CSSで作る。S00〜S03の4画面内に所属選択・成績入力・判定履歴を配置する。添付便覧の全学部課程を対象にするが、全マスタ・画面が実装済みという意味ではない。

## 1. 画面一覧

| ID | 画面 | 操作・表示 |
|---|---|---|
| S00 | ログイン | ログイン識別子・パスワード入力、日本語エラー |
| S01 | ダッシュボード・所属選択 | 所属・適用課程の選択保存、最新の必要・修得・算入・不足、達成概要 |
| S02 | 成績入力・科目一覧 | 既知科目の絞り込み・検索、本人成績の入力・訂正・取消・保存 |
| S03 | 卒業要件詳細・判定履歴 | 条件詳細、おすすめ、チェック実行、本人の履歴一覧・過去詳細 |

ユーザー名・パスワードによる自己登録・ログイン・復旧コードでの再設定画面を実装する。登録・復旧の成功時に新しい復旧コードを一度だけ表示し、保管確認後にログインへ進む。メールは使用しない。既存PNGはv1.1の閲覧専用画面の参考画像であり、現在の入力・保存・履歴を示す完成図ではない。

## 2. ログインと所属

未認証はS00へ案内し、認証後はS01。パスワードは伏字、失敗理由でアカウントの存在を区別しない。セッション期限切れ・ログアウト後に本人データを表示し続けない。

S01では実在する学部・学科・専攻・コースの選択肢だけを表示する。存在しない階層の入力は求めない。入力欄の見出しは「学部・学科・専攻」とし、選択肢には学部・学科・専攻・コース名だけを表示する。便覧名・版・適用入学年度の確認状態・出典は表示せず、マスタ内に保持する。未整備課程を対応済みと見せない。所属変更前に保存成績への影響を案内し、変更時に成績を削除しない。

最新の総必要・実修得・卒業算入・総不足を分けて表示する。判定はAPIのpassを「達成」、failを「未達成」に変換する。正式な卒業認定ではなく、自己入力した成績に基づく単位要件の確認であると示す。

## 3. 成績入力

科目一覧の列：科目名、開講学部／学科、授業形態、開講学期、本人課程の区分・科目群・種別、科目単位、成績、修得状況。課程科目は未履修も表示し、他学部科目も検索して追加できる。

必須フィルタは科目区分・開講学部／学科・開講学期。複数条件はANDで適用する。学期は科目の開講期であり成績記録の履修学期と分ける。学科選択肢は開講学部に対応するものに限定する。絞り込みで非表示となった本人の成績を消さない。

学生は科目一覧から選びS/A/B/C/D/Xを入力する。未確定は別の状態選択、未履修は記録なし。科目単位数とマスタの分類・要件は編集できない。再履修は履修回次ごとの入力を扱い、一覧の代表成績は共通判定規則に従う。再履修（次の回次）は直前の回次が確定した不合格（D・X）の場合だけ追加でき、合格・未確定の後には追加できない。前の回次はD・Xだけを選べ、削除は最新回次だけ行える。履修年度・学期は任意入力とし、本人の履修年度・学期と修得状況でも絞り込める（年度と学期は同じ回次で一致させる）。時系列の専用履歴画面は必須にしない。

修得済みは背景色と「修得済み」ラベルを併記する。不合格D、未受験による不合格X、未確定、未履修を区別する。本人の保存前取消は入力を取り除く操作で、大学への履修取消ではない。

保存ボタンは全成績集合をPUTする。表示中のフィルタ結果だけでなく、非表示の入力を含む全集合を保持して送る。全件取消や所属変更は意図を確認する。未保存変更、保存中、保存済み、保存失敗、別画面・別タブによる版競合を区別する。失敗時に入力を失わせず、競合は再取得・変更内容の確認を案内する。

学生向けJSONファイル読み込み・エクスポートは後回しであり、初期画面にファイルボタンは設けない。APIのJSON通信は画面の通常操作として行う。

## 4. 要件詳細・おすすめ

総単位、分類合計、必修、選択必修群、内訳、選択算入の必要・修得・算入・不足・pass/failを表示する。独立最低値のない分類は「個別最低単位なし」。親子の不足を単純合算しない。

未修得必修名、超過換算の配分、他学部科目の算入先・共通上限・非算入の理由を表示する。例：他学部の対象科目8単位に6単位の上限がある場合「修得8／算入6／上限超過2」。上限規則を確認していない課程へこの数値を使わない。

おすすめは不足条件を補える未修得候補を必修優先・開講学期順で表示し、推薦理由と本人の現在の修得状態を併記する。学習モデルを必須にしない。開講予定・履修許可を保証する表示はしない。

## 5. 最新表示と過去の結果

最新表示はGETによる現在の保存成績の計算で、履歴を増やさない。チェックボタンは未保存変更がある間は先に保存を案内し、保存成績版を指定してPOST /api/checksを実行する。保存完了後に結果ID・判定日時と履歴を表示する。

本人履歴の一覧を新しい順に表示し、選択すると過去の入力と結果を表示する。「過去の判定」、判定日時、当時の課程・規則版を明示する。成績・マスタ更新後も当時の結果を表示し、最新判定へ戻る操作を用意する。本人だけが閲覧でき、共有・公開ボタンは設けない。

## 6. 共通状態と遷移

S01〜S03は共通ナビゲーションとログアウトを備える。PCを主対象に狭い画面は表の横スクロール、キーボードフォーカス、文字ラベルを用意する。

| 状態 | 表示 |
|---|---|
| 読み込み中 | 取得中と表示し、古い結果を最新と誤表示しない |
| 正常な成績0件 | 修得0、未履修、未達成 |
| 入力・保存エラー | APIのdetail文字列を表示し、入力を保持する |
| 設定・規則不足 | 対象と理由を表示し、確定判定を出さない |
| 通信・DB障害 | 日本語の失敗メッセージと再試行 |
| 未認証・期限切れ | 再ログインを案内 |
| 過去結果 | 当時の日時・版を明示し、最新と区別する |

APIのJSONそのものではなく、detailにある日本語メッセージを表示する。エラーを「未達成」や0単位へ変換しない。

分類階層・単位・授業形態・開講学期を表示する。同学年の前期と後期は「前期・後期」にまとめる。
便覧順・科目名順・単位数の少ない順／多い順・開講学年と学期順で並べ替えられる。

これらの元データはマスタ内に保持する。

開発用科目一覧内の課程切替は本人の所属を保存しない。ユーザー名登録・復旧・ログイン後は本人の所属設定を表示し、課程・カリキュラムの保存・再取得・再ログイン後の復元に対応する。保存失敗時は選択を保持し、競合時は確認の上で再取得する。入学年度未確認は未確認のまま表示する。科目一覧は折りたたみの開発用プレビューから開ける。開発用科目一覧API自体は引き続き認証なし・明示的有効化が必要。S01の判定概要、S02〜S03の成績入力・判定画面は今後実装する。
Go単体の既定と`backend-dev`では開発用科目一覧APIを無効にする。画面確認はリポジトリルートの`task dev` / `make dev`で、バックエンドだけの科目一覧確認は`task backend-subject-list` / `make backend-subject-list`で有効にする。待受と起動手順は[バックエンドの構成](../backend_architecture.md)を参照する。

### 2026年10月16日の操作・状態表示の整備

実装済みの認証・科目閲覧の範囲で、既存の配色・画面構成を保ちながら次を整備した。

- 認証フォームは日本語の入力エラーと対象入力欄を関連付け、対象欄へフォーカスする。API失敗時は入力を保持し、ログイン・登録・復旧の切替時は前画面のAPIエラーを解除する。
- 復旧コードはコピー操作を備え、失敗時は手動コピーを案内する。保管確認後にログインへ進み、コード表示を終了する。
- セッションの期限到達と画面復帰時の失効確認では、科目一覧を外して再ログインを案内する。別タブでのログアウトも反映する。
- 課程選択は取得中・取得失敗・選択肢なしを区別する。科目の再試行では課程の選択肢と選択値を維持する。
- 課程一覧0件、選択課程の科目0件、検索結果0件を別の状態として表示する。検索結果0件からも条件を一括解除できる。条件がない場合は解除ボタンを無効にする。
- 課程切替で検索条件を解除し、並べ替えの選択は維持する。狭い画面では検索項目を1列にし、科目表だけを横スクロールさせる。

検証した操作と範囲は[フロントエンドの構成](../frontend_architecture.md)を参照する。
本人の所属保存は別途追加された所属設定画面で扱う。成績の保存、卒業判定・履歴は引き続き未実装である。

## 成績入力画面の実装（2026年10月16日）

ログイン後は所属設定済みなら成績入力、未設定ならマイページを表示する。マイページは共通ヘッダー右上のユーザーメニューから開く。切り替えても各画面の未保存入力は保持する。所属と成績は同じ更新版を共有するため、一方で保存すると、未保存の変更がないもう一方の画面は最新を再取得する。所属未設定では成績入力にマイページへの案内を表示し、所属の保存後に科目と成績を自動で再取得する。

科目一覧は本人課程の科目表の科目を便覧順に先に並べ、続けて課程外の既知科目を表示する。課程外の科目は「本人課程の科目表になし」とし、分類・算入先を推測しない。絞り込みは科目名・科目コード、科目区分（子孫を含み、階層を字下げで表示）、開講学部・開講学科、開講学期、修得状況、履修年度、履修学期のAND。現在のマスタはCS学部だけで学科がないため、開講学科は選択肢がなく無効になる。

成績は科目行で回次ごとに選び、修得済みの行は背景色と「修得済み」ラベルを併記する。変更した行に「未保存の変更あり」を表示する。保存は全集合を送り、全件取消は確認してから送る。409では保存を止めて再取得を案内し、再取得時に未保存の変更があれば破棄を確認する。見出し下に自己申告・判定未対応などの説明文は表示しない。見出しの課程名は所属設定と同じ「学部 ／ 学科 ／ 専攻 ／ コース」の表記とし、便覧名・適用入学年度の確認状態は表示しない。科目の区分・開講学期・開講元・学年共通開講の表示は開発用科目一覧と共通の表示部品を使う。

## 現在の卒業要件チェック画面（2026年10月16日）

成績入力画面に「卒業要件をチェック」を配置する。保存済みの成績を読み取り、
達成／未達成、必要・修得・算入・不足単位、条件別の表、未修得必修、超過換算を表示する。出典情報はデータとして保持し、判定結果には表示しない。
未保存の変更がある場合は保存を促してボタンを無効にする。判定中・失敗・再試行を表示し、
現在の2026年度便覧に基づく判定結果は、適用入学年度が未確認でも表示する。成績0件なら未達成と不足単位を表示する。
判定エラーに達成／未達成を付けない。所属や保存済み成績が変わった場合は古い結果を隠す。
この段階では履歴を作らず、おすすめ科目は表示しない。

条件別判定は「すべて／実学基礎／専門基礎／専門教育」のボタンで切り替える。初期選択は「すべて」とし、各区分では区分合計と子孫の条件を元の順序で表示する。区分はAPIの区分合計から生成し、人文・社会などは親条件をたどって分類する。グラフと総単位の概要は全体表示を維持する。未修得必修科目は判定データに区分情報がないため「全区分」と明示して全件表示する。

判定結果の冒頭にインフォグラフィックを置く。「総単位の充足率」はAPIの算入単位／必要単位を円形グラフにし、区分合計は横棒で表示する。グラフの長さは100%を上限とし、算入単位の数値は実数を表示する。総単位の充足率を卒業要件全体の達成率と混同しないよう明記し、総単位だけ達成している場合は必修・内訳などの未達成条件が残ることを伝える。

結果表示・再判定時に約1秒で円弧と数値が増え、区分別バーが順に伸びる。一度再生したら停止し、画面離脱時は描画処理を解除する。OSの「動きを減らす」設定では初めから最終値を表示する。読み上げにはアニメーション中も最終値を提供する。スマートフォンでは円形グラフと区分別バーを縦に並べる。

## マイページとユーザーメニュー（2026年10月16日）

所属設定画面をマイページに変更する。卒業要件チェックは引き続き成績入力画面で扱い、マイページに判定結果や進捗グラフは置かない。
共通ヘッダーの右上にユーザー名付きの開閉ボタンを置き、「マイページ」「ログアウト」を表示する。従来のログイン中表示・ログアウト専用行と「所属設定」の画面切替は廃止する。未ログイン時はメニューを表示しない。

マイページは「アカウント情報」（ユーザー名の表示のみ）と「所属情報」で構成する。設定済みの所属は既存の共通表記で表示し、「変更する」で選択・保存欄を開く。未設定の場合は最初から編集欄を表示する。保存成功後は編集欄を閉じて完了を伝え、失敗・競合時は選択を保持する。成績入力へ戻る操作と、所属設定後に成績入力へ進む操作を用意する。

初期画面は本人所属の最初の取得成功時だけ決定する。所属保存や他画面の保存による再取得では、自動で別画面へ移動しない。画面切替時の所属・成績の未保存入力保持、共有する更新版と競合処理を維持する。

メニューはEnter・Spaceで開閉し、Tabで項目を操作できる。Escapeでは閉じて開閉ボタンへフォーカスを戻し、外側のクリック・フォーカス移動でも閉じる。非表示の項目・編集欄はフォーカス対象から除く。メニューと所属編集欄の開閉は180msのCSSトランジションとし、prefers-reduced-motionでは無効にする。スマートフォンでは長いユーザー名を省略表示し、画面全体の横はみ出しを防ぐ。

### 他学部配分の注意と入力案内

上限超過かつ複数算入先がある判定結果だけに、取得順・同時期の最適配分はアプリの仮定であり大学の扱いと異なる場合がある旨を表示する。区分別の修得・算入・自由科目の内訳を展開でき、自由科目は卒業要件に算入しない旨を併記する。配分に影響する取得年度・学期が欠けている場合は、既存の成績編集欄で入力・保存して再判定するよう案内する。上限以内・単一区分・時期が配分に影響しない場合は追加入力を求めない。
