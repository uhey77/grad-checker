# 学生向け画面設計

文書版：1.4（2026年10月15日更新）。[RDD](../RDD.md)を基準とし、React / TypeScript / CSSで作る。S00〜S03の4画面内に所属選択・成績入力・判定履歴を配置する。添付便覧の全学部課程を対象にするが、全マスタ・画面が実装済みという意味ではない。

## 1. 画面一覧

| ID | 画面 | 操作・表示 |
|---|---|---|
| S00 | ログイン | ログイン識別子・パスワード入力、日本語エラー |
| S01 | ダッシュボード・所属選択 | 所属・適用課程の選択保存、最新の必要・修得・算入・不足、達成概要 |
| S02 | 成績入力・科目一覧 | 既知科目の絞り込み・検索、本人成績の入力・訂正・取消・保存 |
| S03 | 卒業要件詳細・判定履歴 | 条件詳細、おすすめ、チェック実行、本人の履歴一覧・過去詳細 |

ユーザー名・パスワードによる自己登録・ログイン・復旧コードでの再設定画面を実装する。登録・復旧の成功時に新しい復旧コードを一度だけ表示し、保管確認後にログインへ進む。メールは使用しない。既存PNGはv1.1の閲覧専用画面の参考画像であり、現在の入力・保存・履歴を示す完成図ではない。

## 2. ログインと所属

未認証はS00へ案内し、認証後はS01。パスワードは伏字、失敗理由でアカウントの存在を区別しない。セッション期限切れ・ログアウト後に本人データを表示し続けない。

S01では実在する学部・学科・専攻・コースの選択肢だけを表示する。存在しない階層の入力は求めない。適用カリキュラムと根拠年度を併記し、未整備課程を対応済みと見せない。所属変更前に保存成績への影響を案内し、変更時に成績を削除しない。

最新の総必要・実修得・卒業算入・総不足を分けて表示する。判定はAPIのpassを「達成」、failを「未達成」に変換する。正式な卒業認定ではなく、自己入力した成績に基づく単位要件の確認であると示す。

## 3. 成績入力

科目一覧の列：科目名、開講学部／学科、授業形態、開講学期、本人課程の区分・科目群・種別、科目単位、成績、修得状況。課程科目は未履修も表示し、他学部科目も検索して追加できる。

必須フィルタは科目区分・開講学部／学科・開講学期。複数条件はANDで適用する。学期は科目の開講期であり成績記録の履修学期と分ける。学科選択肢は開講学部に対応するものに限定する。絞り込みで非表示となった本人の成績を消さない。

学生は科目一覧から選びS/A/B/C/D/Xを入力する。未確定は別の状態選択、未履修は記録なし。科目単位数とマスタの分類・要件は編集できない。再履修は履修回次ごとの入力を扱い、一覧の代表成績は共通判定規則に従う。時系列の専用履歴画面は必須にしない。

修得済みは背景色と「修得済み」ラベルを併記する。不合格D、未受験による不合格X、未確定、未履修を区別する。本人の保存前取消は入力を取り除く操作で、大学への履修取消ではない。

保存ボタンは全成績集合をPUTする。表示中のフィルタ結果だけでなく、非表示の入力を含む全集合を保持して送る。全件取消や所属変更は意図を確認する。未保存変更、保存中、保存済み、保存失敗、別画面・別タブによる版競合を区別する。失敗時に入力を失わせず、競合は再取得・変更内容の確認を案内する。

学生向けJSONファイル読み込み・エクスポートは後回しであり、初期画面にファイルボタンは設けない。APIのJSON通信は画面の通常操作として行う。

## 4. 要件詳細・おすすめ

総単位、分類合計、必修、選択必修群、内訳、選択算入の必要・修得・算入・不足・pass/failを表示する。独立最低値のない分類は「個別最低単位なし」。親子の不足を単純合算しない。

未修得必修名、超過換算の配分、他学部科目の算入先・共通上限・非算入の理由を表示する。例：他学部の対象科目8単位に6単位の上限がある場合「修得8／算入6／上限超過2」。上限規則を確認していない課程へこの数値を使わない。

おすすめは不足条件を補える未修得候補を必修優先・開講学期順で表示し、推薦理由と本人の現在の修得状態を併記する。学習モデルを必須にしない。開講予定・履修許可を保証する表示はしない。

## 5. 最新表示と過去の結果

最新表示はGETによる現在の保存成績の計算で、履歴を増やさない。チェックボタンは未保存変更がある間は先に保存を案内し、保存成績版を指定してPOST /api/checksを実行する。保存完了後に結果ID・判定日時と履歴を表示する。

本人履歴の一覧を新しい順に表示し、選択すると過去の入力と結果を表示する。「過去の判定」、判定日時、当時の課程・規則版を明示する。成績・マスタ更新後も当時の結果を表示し、最新判定へ戻る操作を用意する。本人だけが閲覧でき、共有・公開ボタンは設けない。

## 6. 共通状態と遷移

S01〜S03は共通ナビゲーションとログアウトを備える。PCを主対象に狭い画面は表の横スクロール、キーボードフォーカス、文字ラベルを用意する。

| 状態 | 表示 |
|---|---|
| 読み込み中 | 取得中と表示し、古い結果を最新と誤表示しない |
| 正常な成績0件 | 修得0、未履修、未達成 |
| 入力・保存エラー | APIのdetail文字列を表示し、入力を保持する |
| 設定・規則不足 | 対象と理由を表示し、確定判定を出さない |
| 通信・DB障害 | 日本語の失敗メッセージと再試行 |
| 未認証・期限切れ | 再ログインを案内 |
| 過去結果 | 当時の日時・版を明示し、最新と区別する |

APIのJSONそのものではなく、detailにある日本語メッセージを表示する。エラーを「未達成」や0単位へ変換しない。

## ローカル確認画面の実装（2026年10月11日）

ユーザー確認により、まず認証なしのローカル閲覧用科目一覧をReact / TypeScript / CSSで実装した。
CS学部4課程の切替、科目名検索、区分・必修種別・学期・開講学部のAND絞り込み、
分類階層・単位・授業形態・開講学期を表示する。同学年の前期と後期は「前期・後期」にまとめる。
便覧順・科目名順・単位数の少ない順／多い順・開講学年と学期順で並べ替えられる。
狭い画面は表を横スクロールする。
取得中・通信失敗／再試行・マスタ未登録・検索結果0件を区別する。
「ローカル確認用」、便覧の年度・出典、適用入学年度の未確認表示、便覧注記の展開、見出し下と一覧下の説明文は表示しない。
これらの元データはマスタ内に保持する。

開発用科目一覧内の課程切替は本人の所属を保存しない。ユーザー名登録・復旧・ログイン後は本人の所属設定を表示し、課程・カリキュラムの保存・再取得・再ログイン後の復元に対応する。保存失敗時は選択を保持し、競合時は確認の上で再取得する。入学年度未確認は未確認のまま表示する。科目一覧は折りたたみの開発用プレビューから開ける。開発用科目一覧API自体は引き続き認証なし・明示的有効化が必要。S01の判定概要、S02〜S03の成績入力・判定画面は今後実装する。
Go単体の既定と`backend-dev`では開発用科目一覧APIを無効にする。画面確認はリポジトリルートの`task dev` / `make dev`で、バックエンドだけの科目一覧確認は`task backend-subject-list` / `make backend-subject-list`で有効にする。待受と起動手順は[バックエンドの構成](../backend_architecture.md)を参照する。
