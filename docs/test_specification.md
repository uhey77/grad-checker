# テスト仕様

文書版：1.3。[RDD](RDD.md)第12章のT01〜T24を受入基準とする。pytestで判定の単体テストとSQLite / FastAPIの結合テストを実装する。画面はReact / TypeScriptの操作確認を行う。本書のケースは未実行のテスト設計であり、アプリの合格実績ではない。

## 1. フィクスチャと再現性

JSONシードで科目・課程・分類・要件・算入規則とテストアカウントA/Bを投入する。A/Bは別の保存成績・判定履歴を持つ。各課程の必要値は照合済みのマスタを使用し、全学部へCS総124を流用しない。CS例を使うテストは明示的に対象課程を固定する。

未履修、不合格、未確定、再履修、全達成、総算入不足、必修だけ不足、内訳不足、他学部の対象・非対象、共通上限、未確認規則、所属未設定、入力版競合、履歴後の更新を用意する。偽の集計値だけで必修集合の検証を代替しない。

## 5. 性能・起動・ドキュメント

200科目程度の有効マスタと成績で判定APIが1秒以内に応答することを測定する。チェックAPIは計算と結果保存を含める。テスト環境、コールド／ウォーム状態、計測回数と各所要時間を記録する。全課程総データ・履歴増加時は別途測定し、この基準を無条件に保証しない。

READMEの手順に従って第三者がDB初期化・JSONシード投入・API／React起動・pytest実行を再現できること、Swagger UIに現在のパスと入力・出力・エラーが掲載されることを確認する。学生向けJSONファイル入出力と公開共有は受入対象にしない。
