# 卒業要件判定ロジック設計

文書版：1.3。[RDD](RDD.md)第6〜7章が基準。Pythonの共通判定関数をチェック・ダッシュボードのブリッジアダプターから利用し、pytestで検証する。実装済み範囲は次節のとおりで、本書全体の実装完了を意味しない。

## 現在の実装範囲（2026年10月16日）

`backend/modules/requirements/grad_checker_requirements/application/evaluation.py` の
`evaluate_graduation(EvaluationSnapshot)` を実装した。DB・HTTPに依存せず、所属課程・
適用カリキュラム・成績版・成績・科目マスタ・要件マスタの整合した入力を受け取る。
マスタは既存の投入用Pydantic契約を共有し、関数入口で独立コピーを再検証する。
同一時点のDB読取りは `SqliteEvaluationRepository`、本人認可はブリッジアダプターが担当する。

修得状態、最新履修回次、重複排除、総単位・最上位区分合計、必修集合、選択必修群、
内訳最低、直接選択と確認済みの同区分超過換算を計算する。結果には条件名・必要・修得・
算入・不足、未修得必修の科目情報、換算内訳、成績版・カリキュラム情報・規則版を含む。
選択合計の修得単位は直接選択と対象他学部科目の実単位、算入単位は直接選択・超過換算・上限内の他学部算入を合計した値である。自由科目は修得には含めるが算入には含めない。
総単位条件のpassと全体のpassは別で、全体は全条件の達成を必要とする。

CS4課程のマスタ構造に対応し、課程の全科目を含む総単位条件、各最上位区分の合計・
選択条件、必修・選択必修の漏れや重複を検証する。必要単位数や条件数は固定しない。
現在は本人が選択・保存した2026年度便覧のカリキュラムを判定基準として使用する。
適用入学年度の確認状態は判定を止める条件にせず、正常な成績0件はfailと不足単位を返す。
適用入学年度のnull・unverifiedは根拠情報として保持し、確認済みへ書き換えない。
未確認の超過換算は、実際に超過が発生してその規則が必要な場合に、規則IDと保存された理由を
持つ`EvaluationError`を返す。CS2026の実学基礎の換算は冊子94注1・注2を再確認して確認済みに改訂した。超過換算と人文・社会の各2単位条件を独立して計算し、内訳不足は通常のfailにする。

本人データのDB読取り、GET /api/me/graduation-requirements、判定日時の付与まで実装済み。
成績入力画面のチェックボタンと結果表示まで接続済み。
他学部算入は、明示的な対象科目・算入先と配分方針が登録された規則について対応した。
実シードの他学部対象科目は未転記のため、実際の他学部科目利用にはマスタ整備が必要。
算入先未登録の課程外科目はエラーにし、黙って除外しない。おすすめと履歴一覧は未実装。判定履歴の保存・本人の過去結果取得は実装済みで、保存結果に推薦はまだ含まない。
`backend/tests/test_requirement_evaluation.py` は架空課程と実シードのCS4課程で計算を検証する。
`test_external_allocation.py` は架空の照合済み他学部科目で取得順・最適配分・入力要求を検証する。
実シードを変更しないCS4課程でも、成績0件と必修科目修得時の計算を単体・実HTTPで検証する。

## 1. 入力と出力

入力は、本人の保存済み所属・適用カリキュラム、成績版、成績履歴、課程別科目・条件・算入規則の整合したスナップショット。科目単位数は正の整数、必要値・上限は非負整数。CS先進情報の20条件・総124単位を全課程へ固定しない。

成功結果は `result: pass / fail`。画面では達成／未達成と表示する。条件別もpass/fail。成績記号のS/A/B/C/D/Xとは別の値である。設定不足や未確認規則は成功したfailではなくエラーにする。

出力は課程・規則版・成績版・判定時刻、総必要・総修得・総算入・総不足、分類別と条件別の内訳、未修得必修、換算、他学部算入、おすすめ。科目名・分類・条件名・必要値・推薦理由は結果に含め、履歴再取得時に現在のマスタを参照して置き換えない。

## 2. 成績と重複排除

| 入力 | 修得状態 | 実単位 |
|---|---|---|
| finalized + S/A/B/C | earned（修得済み） | 科目単位 |
| finalized + D | not_earned（不合格） | 0 |
| finalized + X | not_earned（未受験による不合格） | 0 |
| pending + grade=null | pending（未確定） | 0 |
| 記録なし | not_taken（未履修） | 0 |

同一科目の回次は1からの連番で、再履修は確定した不合格（D・X）の後だけ入力できる。このため合格は高々1件で常に最新回次となり、最新の履修回次を代表とする。代表成績・年度・学期は同一履歴から取る。同じ科目を重複加算しない。入力取消は本人の履歴を削除して再計算する操作であり、大学の公式成績変更ではない。

未知科目・未知記号・finalized+null・pending+成績記号・回次重複・回次の欠番・合格または未確定の後の回次は入力エラー。認定Rは今回の学生入力対象外。0単位やDへ黙って読み替えない。

## 3. 条件と配分

必修は対象科目集合の全修得を確認する。選択・選択必修の余剰で必修を補わない。選択必修は課程別の群・内訳を独立判定し、別群の余剰で不足を補わない。条件の親子集合は重なりを表示できるが総単位に重複加算しない。

確認済み規則が同区分超過換算の場合：

```text
群への算入 = min(群の修得単位, 群の必要単位)
超過候補 = max(群の修得単位 - 群の必要単位, 0)
選択への算入 = 直接選択の対象単位 + 規則で許された超過換算 + 対象他学部科目の配分
条件別不足 = max(条件必要単位 - 条件算入単位, 0)
総不足 = max(総必要単位 - 重複排除・上限適用後の総算入単位, 0)
```

換算は実単位を増やさない。別科目区分への換算や、独自の最低値を追加しない。実単位が124でも上限等で総算入が122なら、必要124の総不足は2単位。

## 4. 他学部科目

開講元の学部・学科、授業形態、課程別分類・種別、所属先の適用規則から対象と算入先を決める。修得した全科目の実単位と、卒業に数える算入単位を分ける。

冊子53の4学部共通規則では対象他学部講義の合計上限は6。専門基礎は所属先の専門基礎選択へ、専門教育は専門教育選択へ算入し、超過分は自由科目。区分ごとに6ずつ数えない。8単位なら最大6算入・2非算入。演習・実習・実験など対象外科目を自動算入しない。他課程には確認した規則だけを適用する。

取得した年度・学期の早い順に共通上限まで算入する。同じ年度・学期で上限に達する場合は、区分合計・選択条件の達成数を最大化し、同数なら不足単位合計を最小化する。同点は分類コード順で固定する。配分は単位数で扱い、上限超過分は自由科目とする。この配分順序は大学の正式規則ではなく、2026年10月16日にユーザーが合意したアプリの仮定である。

`allocation_policy=chronological_best_fit_v1` を明示した規則でだけこの方針を使う。大学規則の確認状態はunverifiedのまま保持する。上限超過かつ複数算入先の場合だけ `provisional_external_allocation` の注意を結果へ返す。取得年度・学期が未入力で区分配分が変わり得る場合は409で入力を案内する。上限以内・単一算入先・時期欠落が上限内外を変えない場合には入力を要求しない。

## 5. 全体判定とおすすめ

総算入、全必修、全選択必修・内訳、選択算入、分類合計の全条件を満たせばpass。1条件でも不足ならfail。総不足だけで判定しない。正常な成績0件は0単位のfailで、設定エラーではない。

おすすめは、未修得の既知科目のうち、不足した必修・条件へ算入可能な候補を返す。まず未修得必修を優先し、次にマスタの開講学期順、同順位は安定した科目ID順とする。同一科目が複数条件に寄与する場合は候補を重複させず理由を併記する。不合格・未確定は修得済みではないので候補になり得るが、履修中など状態を表示する。

開講学期はマスタの順序キーであり、現在受講可能・将来開講予定の保証ではない。学期不明は末尾に表示する。未知の算入規則が必要な推薦は確定しない。機械学習・協調フィルタリングは初期実装に要求しない。

## 6. 保存と再利用

`GET /api/me/dashboard` は共通判定関数で最新の保存成績を計算するが履歴を作らない。`POST /api/checks` は同じ関数で計算し、入力・結果・課程と規則版・成績版・推薦をcheck_resultsへ保存してから結果IDを返す。保存失敗なら成功を返さない。

`GET /api/checks/{id}` は所有者を確認して保存済みJSONを返し、再計算しない。後日の成績訂正・マスタ改訂・所属変更でも過去結果は変わらない。現在の判定へ使うマスタが不整合でも、読み出せる過去結果はそのまま取得できる。

## 7. エラーと検証

分類循環、必修集合・必要値不足、課程不一致、重複する群配分、未知の算入先、非整数単位、成績矛盾、未確認規則を検出する。設定不足はAPI409、未知科目は400、不正形式は422、DB障害は503として[API仕様](api_specification.md)に従う。成功resultに第3の状態はない。
