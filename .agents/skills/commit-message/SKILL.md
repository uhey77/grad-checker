# コミットメッセージの規則

コミットメッセージは次の1行のみとする。本文（body）とフッター（footer）は付けない。

```text
<type>(<scope>): <summary>
```

スコープを省略する場合は、括弧ごと省略する。

```text
<type>: <summary>
```

## type

小文字の以下の種類から、変更内容に合うものを選ぶ。

| type | 内容 |
| --- | --- |
| `build` | ビルドシステムや外部依存の変更 |
| `ci` | CI の設定変更 |
| `docs` | ドキュメントの変更 |
| `feat` | 機能追加 |
| `fix` | バグ修正 |
| `perf` | パフォーマンス改善 |
| `refactor` | 機能・挙動を変えない構造変更 |
| `test` | テストの追加・修正 |
| `revert` | 既存コミットの差し戻し |

## scope

影響を受けるパッケージやモジュールなどを簡潔に記載する。全体に影響する変更や、範囲が明確でない場合は省略する。対象プロジェクトに実在する名称を使う。

## summary

- 日本語で、変更内容を簡潔かつ具体的に記述する。技術用語や識別子は元の表記を使ってよい。
- 「〜を追加する」「〜を修正する」「〜を削除する」のように、現在形の動詞で記述する。
- 日本語には小文字開始の規則を適用しない。
- 文末に句点（。）やピリオド（.）を付けない。
- 空のサマリーや、差分に裏付けられない変更内容を書かない。
- 差し戻しも同じ1行の形式に従い、何を差し戻すか日本語で記述する。本文やフッターに SHA を追加しない。

## 例

```text
feat(forms): 非同期バリデーションを追加する
fix(api): 単位数の集計ミスを修正する
docs: セットアップ手順を更新する
revert(forms): 非同期バリデーションの追加を差し戻す
```

作成後に、type、任意の scope、日本語の空でない summary、文末の句読点なし、本文・フッターなしを確認する。
